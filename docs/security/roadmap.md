## Фаза 1 — Observability-фундамент в приложении

**Полностью делаемо в коде, без внешней инфры.**

1. `micrometer-registry-prometheus` в `backend/build.gradle`,
   `management.endpoints.web.exposure.include` дополнить `prometheus` —
   даёт `/actuator/prometheus` в формате, который `otelcol-contrib`
   ожидает нативно (тот же формат, что уже проверен для numi).
2. Кастомные security-метрики, инструментированные в уже существующих
   choke-point'ах (`GlobalExceptionHandler`, `AuthService`), не размазано
   по сервисам:

   | Метрика | Откуда | Отвечает на |
   |---|---|---|
   | `auth_login_failure_total{reason}` | `handleBadCredentials`/лок-аут-хендлер (LR-026) | M10 (brute-force) |
   | `auth_login_success_total` | `AuthService.authenticate()` | baseline |
   | `auth_register_total` | `AuthService.register()` | ранний сигнал |
   | `authz_denied_total{path,role}` | `handleAccessDenied` | H1 (teacher IDOR), класс LR-023 |
   | `http_unmapped_path_total{path}` | новый интерцептор, см. п.3 | ретроспективно самый ценный — поймал бы LR-023 с первого дня |
   | `backup_job_last_success_timestamp` | Postgres backup CronJob (LR-003) | уже известный пробел — алертинг на бэкап (`tickets.md`, LR-003 п.7) |

3. **"Правильный" CI-guard (не grep по имени зависимости):**
   регрессионный тест, автоваряющий `RequestMappingHandlerMapping` и
   утверждающий, что каждый замонтированный путь либо под `/api/v1/**`,
   либо в явном allow-листе (`/actuator/**`) — обобщение доказавшего
   себя паттерна `SpringDataRestExposureTest` (LR-023), ловит весь класс
   "что-то незаметно домонтировало HTTP-поверхность", не только повтор
   Spring Data REST. Тот же фильтр даёт метрику `http_unmapped_path_total`
   из п.2 — один механизм, две точки применения (CI + runtime).
4. `management.server.port` — отдельный порт для actuator (по образцу
   numi's `9090`), не тот, что слушает бизнес-API. Предусловие для
   Фазы 2, не для Фазы 1 самой по себе.

## Почему не откладывать на "когда понадобится"

Архитектурно предусмотренные, но пока не живые роли `TEACHER`/
`BUSINESS_OWNER` не создают сегодня реальной IDOR-угрозы — единственный
владелец-администратор. В момент реального появления сторонних
преподавателей находки класса H1 перестают быть теоретическими —
`authz_denied_total`-мониторинг должен быть на месте **до** этого
расширения ролей, не после первого инцидента с ним. Та же логика для
реальной оплаты (LR-017, Stripe/Numi) — платёжный трафик радикально
поднимает ставки для всего, что здесь предложено.

- [x] Фаза 1 — закрыта 2026-08-07, `architect-reviewer` approve (нашёл и
      был исправлен реальный пробел до закрытия — см. ниже). Все 4 пункта
      реализованы:
      1. `micrometer-registry-prometheus` + `/actuator/prometheus`.
      2. Метрики в choke-point'ах — реализованы как специфицировано, **с
         одним осознанным отклонением**: `authz_denied_total` и
         `http_unmapped_path_total` реализованы БЕЗ тегов `path`/`role`
         (спецификация выше в этом файле их предполагала). Причина:
         raw-path/role как значение тега — известный источник
         неограниченной кардинальности в Prometheus/Micrometer (сканер
         путей или похожий пробник может намайнить произвольное число
         уникальных значений тега). Общий счётчик — безопасный дефолт;
         добавить ограниченный тег (например, класс контроллера вместо
         сырого пути) можно позже, если разбивка по эндпоинту реально
         понадобится. См. комментарий в `GlobalExceptionHandler.java`.
      3. "Правильный" CI-guard — `backend/src/test/java/com/be/
         ApiSurfaceAllowlistTest.java`, ДВА теста, не один:
         - путь-based (как специфицировано) на
           `RequestMappingHandlerMapping`;
         - **добавлено сверх спецификации** после находки
           `architect-reviewer`: enumeration всех бинов `HandlerMapping`
           по имени. Причина: spring-data-rest (LR-023) регистрирует
           auto-exposed пути внутри `DelegatingHandlerMapping` — обёртки
           над `RepositoryRestHandlerMapping`/`BasePathAwareHandlerMapping`,
           которые НИКОГДА не публикуются как отдельные Spring-бины, то
           есть invisible для любой проверки, читающей только
           `RequestMappingHandlerMapping`. Путь-only версия теста НЕ
           поймала бы LR-023, если бы существовала на момент инцидента —
           только двухслойная версия (путь + перечисление бинов
           HandlerMapping) ловит фактический механизм. Также: `/actuator/**`
           не нужен в allow-листе пути-based теста — `WebMvcEndpointHandlerMapping`
           не является подтипом `RequestMappingHandlerMapping`
           (sibling-класс), поэтому actuator-пути физически не видны
           этому конкретному бину независимо от порта — исходное
           предположение спецификации об `/actuator/**` в allow-листе
           было основано на неверной ментальной модели, скорректировано
           в коде теста.
      4. `management.server.port=9090` — Helm-пробы
         (`backend-deployment.yaml`) и CI smoke-test (`.gitlab-ci.yml`)
         обновлены в том же дифе, чтобы не сломать деплой; `backend-service.yaml`
         сознательно не изменён — порт остаётся недоступен через публичный
         Service/Ingress, что и держит его закрытым до полноценной Фазы 2
         NetworkPolicy.
