# docs/ — Lebens Rhythmus documentation index

> **Language:** Russian по умолчанию (см. корневой `CLAUDE.md` →
> Language conventions). Явные исключения фиксировать так же явно, как
> сделано в numi, если появятся.

Эта папка — единственный источник истины про **почему** и **как** были
приняты решения по LR, и где что искать. Код отвечает на *что*; эти файлы
— на *почему* и *что дальше*.

## Структура

| Папка | Роль | Частота обновления |
|---|---|---|
| `context/` | AI-facing — что грузит Claude Code (always/on-demand/grep-only, см. корневой `CLAUDE.md`) | По тикету / по сессии |
| `product/` | Зачем существует LR, для кого, открытые вопросы | Редко / по мере вопросов |
| `architecture/` | Как построено — диаграммы слоёв, ADR, исторические чекпоинты (`erm.drawio`, `infrastructure_scheme.drawio` — старт проекта, см. пометку в корневом `CLAUDE.md`) | ADR: никогда не удалять, только добавлять или помечать Superseded |
| `infra/` | Референс по инфраструктуре — топология, узлы, DNS, Cloudflare Tunnel (`INFRA-LR.md` — единая точка входа) | При изменении инфры |
| `runbooks/` | Пошаговые рецепты восстановления после сбоя (`infra-fix-shutdown.md`) — процедурные, для 2 ночи во время инцидента, не для спокойного чтения | При новом классе инцидента |
| `compliance/` | Юридический/regulatory журнал (DSGVO, данные детей) | При каждом compliance-значимом изменении |
| `adr/` | Резерв: standalone ADR-файлы, если/когда `architecture/decisions.md` станет слишком большим (по аналогии с numi `docs/adr/`) | Пока не используется |
| `strategy/` | Резерв: GTM/монетизация/дорожная карта (по аналогии с numi `docs/strategy/`) | Пока не используется |
| `decision-history/` | **Архив.** Устаревшие планировочные доки — не текущие инструкции | Append-only, никогда не как текущая истина |
| `tickets/` | Единственный тикет-трекер (`tickets.md` активный, `archive.md` закрытые) | Каждый спринт |
| `user/` | Документация для конечных пользователей (родители/участники) | Когда появится |

## Правила

1. **Коммить эти файлы в git.** Они ценнее большей части кода.
2. **Никогда не удалять ADR** — помечать `Superseded by ADR-XXX` вместо
   удаления, в `architecture/decisions.md` (когда заведём — пока ADR живут
   в `PROJECT_INDEX.md` §8).
3. **`decision-history/` — не текущая истина.** Если что-то там
   противоречит `architecture/decisions.md` или актуальному
   `PROJECT_INDEX.md` — побеждает последний.
4. **Один тикет-трекер.** `tickets/tickets.md` — единственный активный
   backlog. Второй найденный — считать устаревшим, архивировать, не вести два.
5. **Писать ADR в момент решения**, не задним числом.
6. Корневой `CLAUDE.md` — то, что реально читает Claude Code для навигации
   по этой папке — держать в синхроне при переносе папок. Этот README — для
   людей.

## Рекомендуемый порядок чтения для нового участника (или новой Claude-сессии)

1. `context/PROJECT_INDEX.md` — что мы строим, стек, известные пробелы
2. `context/KNOWN_ISSUES.md` — куда не наступать снова
3. `infra/INFRA-LR.md` — топология инфраструктуры, `runbooks/infra-fix-shutdown.md` — как чинится при сбое
4. `context/CODING_PROTOCOL.md` — правила для AI-ассистента при написании кода

## `ops/` → `infra/` + `runbooks/` (решение 2026-07-20)

Было предложено просто перенести всё в `docs/infra/`. Решили иначе: разделить по
**типу чтения**, а не просто по теме — в инциденте в 2 ночи ищешь пошаговый
рецепт, а не топологию с обоснованиями. `docs/infra/` — справочник ("что и
почему так построено"), `docs/runbooks/` — процедуры ("что делать прямо
сейчас"). Заодно `docs/runbooks/` уже существовал как пустая заготовка,
скопированная по аналогии с numi (`docs/runbooks/monitoring.md` там) — так
оба сестринских проекта используют одно и то же имя для одного и того же типа
документа. `docs/ops/` как отдельная директория убрана.
